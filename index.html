XML Signature · XML Encryption · PHP · Node.js

Signed tokens,
and proof of who signed them.

ezxmldsig creates and verifies XML tokens: user data, timestamped, signed with the key of their sender and, if need be, encrypted for their receiver. A receiver accepts a token only if its certificate descends from the certification authorities it trusts. Use them for single sign-on, or to pass any data whose origin must be proven. Why?

Each library reads the tokens of the other, signed or encrypted, and refuses the same forged tokens with the same errors: a single sign-on can mix applications written in PHP and in Node.js. The tokens follow the W3C standards XML Signature and XML Encryption.

The Node.js library also seals files, from its version 2.0.0, as an experimental feature: detached XAdES signatures in an ASiC-E container, which validators of electronic signatures such as DSS, the validator of the European Commission, accept. The PHP library does not seal files yet.
